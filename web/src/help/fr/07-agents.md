Confiez du travail à Claude Code sans quitter Prism : chaque agent tourne dans un vrai terminal de l’app, dans son propre worktree si vous le voulez, et Prism vous prévient dès que l’un d’eux a besoin de vous.

## La vue Agents
![La vue Agents : les agents par état à gauche, celui ouvert dans son Chat](images/agents.webp)

Ouvrez-la avec le bouton **Agents** du rail, ou le chiffre qui suit votre dernière page (`⌘6` avec cinq pages). Chaque agent est une session `claude` dans un terminal maintenu en vie par tmux : quitter Prism ne l’arrête pas, et Prism s’y rattache à son retour.

> [!NOTE]
> Les agents ont besoin de `tmux` dans le PATH : sur macOS `brew install tmux`, sous Linux le paquet de votre distribution, sous Windows une version compatible tmux dans le PATH. Sans lui, la vue Agents reste indisponible.

La liste à gauche montre vos agents et vos sessions Claude Desktop ensemble, groupés par statut :

- **Vous attend** : Claude vous pose une question (*Attend votre réponse*) ou veut une autorisation (*Outil ou autorisation*). La ligne dit ce qu’il attend.
- **En cours** : Claude travaille.
- **Terminé** : prêt pour la revue, achevé ou inactif.

L’en-tête de la page est le même que sur les autres pages : son filtre (un ticket, une MR, un mot) ne garde que les agents et sessions qui y sont liés, par leur ticket, leur branche et leurs MR. Les filtres **Tous** / **Agents Prism** / **Desktop** restreignent la liste, et le menu **groupe** à côté change le regroupement : par statut (ce que fait Claude), par type (`[[agents.kinds]]`), par étiquette (un groupe par étiquette, un agent qui en a plusieurs dans chacun), par dépôt (celui où il travaille : celui de son worktree, ou le clone qui contient son dossier ; celui d’une session Desktop aussi). Par dépôt, chaque dépôt de la config apparaît comme un projet, qu’un agent y travaille ou non : un **+** ouvre le lanceur court sur lui (le prompt d’abord, le worktree nommé d’après lui, le mode utilisé la dernière fois ; **Plus d’options** pour le reste), **Laissé il y a 6 j** dit où en était son dernier agent fermé (sa branche, ses derniers mots) avec **Rouvrir** pour le reprendre sur sa conversation, et **Ensuite** est son premier ticket à prendre sur un board qui le nomme (Obsidian), ▶ pour l’implémenter ; les projets sans activité depuis deux semaines sont au repos, repliés. Sur le téléphone, **Par projet** dans l’onglet Agents montre les mêmes cartes. Le **type** dit ce que fait un agent — Refinement, Développement, Revue par défaut — sous forme de badge coloré : deviné au lancement d’après la commande par laquelle commence son prompt (`/acme-flow:refine` → Refinement, via les commandes de chaque type), modifiable dans son en-tête. L’avancement du travail, c’est son statut et celui de sa MR. Les **étiquettes** sont libres : plusieurs par agent, saisies dans son en-tête, `#api` dans la liste ; le menu **Toutes les étiquettes** ne garde que les agents qui en portent une. Le bouton ⚙ remplace la liste par **Gérer** : renommez les types (et réglez les commandes qui font chacun) et les étiquettes suggérées (les agents qui en portent une suivent), réordonnez, ajoutez ou supprimez-les, enregistrés aussitôt dans `[agents]` de config.toml ; une étiquette utilisée mais non suggérée peut être gardée, ou retirée de tous les agents. Cliquez sur le titre d’un groupe pour le replier (et à nouveau pour le déplier) : Prism le retient pour chaque regroupement, le compte reste, et un point orange signale qu’un agent du groupe vous attend ; `⌘[` / `⌘]` sautent les groupes repliés. Le menu **tri** ordonne chaque groupe par **Dernière activité** (par défaut : au sein d’un type, ce qui vous attend vient en premier), **Création**, **Nom** ou **Branche** ; Prism retient votre choix. `⌘B` réduit la liste en un rail d’icônes ; `⌘[` / `⌘]` passent à l’agent précédent ou suivant.

Sur le Dashboard, le bloc **Agents** ne montre que les agents de Prism, ceux qui vous attendent en premier, avec des badges pour leur ticket, leur MR, leur CI et le retard de la branche sur sa base. Un clic ouvre l’agent dans la vue Agents.

> [!TIP]
> Quand un agent demande une autorisation, **Autoriser une fois** dans son en-tête répond oui sans passer par le terminal.

## Lancer un agent
1. Appuyez sur `⌘N`, cliquez sur **Nouveau**, ou choisissez une action Claude dans le menu ⋯ d’un ticket ou d’une MR : le lanceur s’ouvre, prérempli.
2. Donnez-lui un **Titre** et un **Prompt**. Le prompt est envoyé tel quel : un prompt simple, ou une commande de compétence comme `/my-plugin:refine` avec un identifiant de ticket.
3. Choisissez **Où** : **Nouveau worktree** (son propre checkout, sur une nouvelle branche `agent/…` partant de la base, ou sur la branche existante de la MR ; **Depuis** choisit une autre branche d’origin dont partir, proposée à la saisie — vide, la base du dépôt —, et les comptes du worktree et son **MR brouillon** suivent cette branche ; avec plusieurs dépôts marqués **Worktrees** dans Réglages › Code › Dépôts, choisissez son **Dépôt**), **Worktree existant**, ou **Dossier**. Le lanceur montre le dossier et la branche qu’il va créer : un nom déjà pris (son dossier, ou sa branche `agent/…`, laissés par un worktree précédent) cède la place au suivant libre (`-2`, `-3`…), comme le lanceur l’indique ; la branche d’une MR déjà extraite dans un autre worktree ne peut pas l’être deux fois, Lancer attend donc que vous choisissiez ce worktree sous **Worktree existant**. Le checkout principal d’un dépôt est partagé : idéal pour un travail en lecture seule comme affiner, relire ou enquêter. Passer de **Dossier** à un worktree garde le dépôt du dossier : il devient le **Dépôt** du nouveau worktree, et **Worktree existant** choisit l’un de ses worktrees.
4. Choisissez l’**Agent** : Claude Code, Command Code, OpenCode ou Codex, pour cet agent seulement. Celui marqué *par défaut* est celui de son dépôt (`[[repos]] agent`), à défaut celui de Réglages › Agents (`[agents] provider`) ; il suit le dépôt choisi sous **Où** jusqu’à ce que vous en choisissiez un autre. Son **Modèle**, pour cet agent seulement et conservé à la reprise : les noms que propose cette CLI sont suggérés (les alias et modèles de Claude Code, le catalogue de Codex, `cmd --list-models`, le catalogue d’OpenCode), tout autre peut être saisi ; vide, le modèle de sa page dans les Réglages, à défaut celui par défaut de la CLI.
5. Choisissez les **Autorisations** : **Par défaut** (le mode de vos réglages Claude), **Accepter les modifications** ou **Planifier d’abord**, et éventuellement un **Type** (**Auto** par défaut : celui que nomme sa commande, affiché à côté) et des **Étiquettes** (cliquez sur une suggérée, ou tapez-en une autre ; Entrée l’ajoute).
6. Vérifiez la ligne **Commande**, qui montre exactement ce qui va tourner, puis **Lancer** (`⌘↩`).

**Plusieurs dépôts.** Dans un nouveau worktree, **Aussi dans** coche d’autres dépôts à worktrees (`[[repos]] worktrees`) : chacun reçoit un worktree du même nom, sur une nouvelle branche du même nom depuis sa propre base, et l’agent travaille dans tous, son CLI recevant les autres (`--add-dir` ; Claude Code et Codex seulement, les autres travaillent dans un seul dossier). Son en-tête les montre (**+ helm**), une reprise les redonne, et le fermer les supprime comme son propre worktree, sauf s’il y a quelque chose à perdre. Son étape **MR brouillon** ouvre une MR dans chaque dépôt qui a des commits, chaque description listant les autres.

**Préparer** au lieu de Lancer déclare l’agent sans le démarrer : il attend dans la liste comme *Préparé*, rien ne tourne et aucun worktree n’existe encore. **Démarrer**, dans son en-tête, le lance tel que préparé (son worktree créé alors, ses étapes **Ensuite** après lui), sous le titre, le type et les étiquettes que vous lui avez donnés entre-temps ; **Modifier…** le rouvre dans le lanceur, et Lancer ou Préparer l’y remplace. Son onglet **Lancement** montre ce qu’il va lancer. L’effet de l’action qui a ouvert le lanceur (un ticket passé en *validation* et qui vous est assigné…) s’applique dès que vous le préparez, comme au lancement. Si votre tracker refuse ce changement, un message dit pourquoi, avec **Réessayer**.

Une action Claude prise hors de la vue Agents (dans le panneau d’un ticket ou d’une MR, Worktrees…) ouvre le lanceur en tiroir au-dessus de ce panneau, compact (**Plus d’options** montre Ensuite, le type, les étiquettes et la commande) : ← ou `Esc` revient au panneau, et une fois lancé vous restez où vous étiez, une notification proposant **L’ouvrir**. Un `⇧`-clic sur une action Claude saute le lanceur et démarre l’agent immédiatement, avec les valeurs par défaut de l’action, et la même notification. **Ouvrir plutôt dans Claude Desktop** garde l’ancien chemin : une session Claude Desktop, prompt non envoyé. Ce n’est proposé que quand les sessions Desktop sont affichées (**Afficher les sessions Desktop**, jamais avec Command Code).

## Travailler avec un agent
Chaque touche va à Claude, sauf les raccourcis `⌘`. Sous Linux et Windows, Ctrl y va à Claude (Ctrl+C, Ctrl+B…) : les raccourcis de Prism prennent Ctrl+Maj dans le terminal d’un agent. `⌘.` interrompt Claude, et `⌘+` / `⌘-` / `⌘0` changent la taille du texte du terminal — pour un agent affiché en Chat, celle du Chat (**Taille du texte du chat**, `[agents] chat_font_size`, Réglages › Agents › Agent ; le téléphone garde la sienne). La molette fait défiler l’historique ; un glisser sélectionne et copie au relâchement, un double-clic un mot, un triple-clic une ligne ; la sélection reste visible jusqu’à un clic ou une touche (la touche va alors à l’agent, comme après avoir fait défiler l’historique). Les liens s’ouvrent par `⌘`-clic (Ctrl-clic sous Linux et Windows), les URL simples comme celles qu’écrit Claude Code. Un ticket ou une MR que l’agent nomme (`ABC-123`, `!1957`) ou vers lequel il pointe (une MR d’un dépôt que Prism lit, un ticket de votre tracker) s’ouvre dans son panneau au-dessus du terminal ; un `⌘⇧`-clic ouvre plutôt un lien dans le navigateur. Tout autre lien — un serveur local comme `http://portfolio.localhost:3000`, une doc — s’ouvre dans le navigateur. Un clic droit (ou `⌃`-clic) ouvre le menu de Prism, **Copier** (une sélection faite par `⌥`-glisser) et **Coller**, jamais celui de tmux. Les accents passent au copier-coller : les panneaux des agents tournent dans une locale UTF-8 ; un agent ouvert avant ce réglage l’obtient après un **Redémarrage**.

L’en-tête a deux rangées. La première dit quoi faire maintenant : le nom de l’agent (double-clic pour le renommer, dans Prism seulement), son état en mots, et la seule action du moment — **Autoriser une fois** quand Claude demande une autorisation (cela répond oui sans passer par le terminal), **Reprendre** quand l’agent est arrêté (cela reprend la conversation, même après un redémarrage de l’ordinateur). À droite, **Fichiers | Diff | Web | Tâches | Shell | Activité | Lancement | Notes** ouvrent le panneau latéral, **Arrêter** fait quitter Claude et garde son dernier écran, et **⋯** contient le reste. La seconde rangée, plus petite, dit où il travaille et comment il est classé, à lire : son ticket (clic pour l’aperçu) et sa MR (clic pour ouvrir son panneau), trouvés dans son titre et sa branche, sa branche (son dossier au survol), son worktree, puis son **type** (un badge coloré) et ses étiquettes. **Modifier** affiche leurs champs : **+ lien** lie un autre ticket ou une autre MR à la main (un identifiant de ticket, ou une MR comme `!123`), × le délie, retour à celui trouvé ; **Type** se change sur place ; × retire une étiquette, **+ étiquette** en ajoute une (les suggérées et utilisées sont proposées) ; **Terminé** revient à la ligne à lire. **Détails de l’en-tête** (`[agents] header_meta`, Réglages › Agents › Agent) réglé sur `edit` garde les champs toujours visibles. Ses ports ouverts s’y affichent aussi, `:5173` en vert : les serveurs que le bloc **Serveurs de dev** trouve pour cet agent (dans ses shells, démarrés par l’agent lui-même, ou un conteneur Compose de son dossier) ; un clic l’ouvre sur http://localhost. La liste les montre sur sa ligne. Rien tant que le bloc Serveurs de dev est désactivé (Réglages › Agents › Serveurs de dev). Dans son Chat, **Autoriser une fois** et **Arrêter** sont dans le dock sous la conversation plutôt que dans l’en-tête.

Le menu **⋯** :

- **Ouvrir son dossier** : dans le Finder, un shell ou votre éditeur ; **Attacher dans …** ouvre aussi l’agent dans votre propre app de terminal.
- **Renommer** ; **Redémarrer** redémarre Claude sur la même conversation, pour qu’il relise les réglages, les hooks, les serveurs MCP et `CLAUDE.md` (un second clic pendant que Claude travaille) ; **Interrompre** arrête le tour en cours, comme `⌘.`.
- **Supprimer le worktree**, une fois l’agent arrêté, supprime son worktree seulement si rien ne serait perdu ; sinon une barre dit pourquoi il est gardé.
- **Fermer** arrête l’agent s’il tourne encore (deux Ctrl-C, quelques secondes pour quitter proprement ; un second clic pour confirmer), termine sa session de terminal et supprime son worktree, et sa branche locale avec, quand rien ne serait perdu (les commits d’une MR mergée comptent comme livrés) et qu’aucun autre agent ni session Claude Desktop n’y travaille ; sinon le worktree reste et un message dit pourquoi. La conversation reste dans l’historique de Claude.

**Fenêtre de contexte** : une barre sous le terminal d’un agent Claude Code montre à quel point son contexte est rempli à sa dernière réponse, les tokens utilisés et combien il en reste (`36% 360k / 1M tokens · 640k left`) ; sa ligne dans la liste, le pourcentage. Ambre au-delà de 70 %, rouge au-delà de 85 % : Claude Code compacte la conversation de lui-même quand elle est presque pleine, et la jauge revient avec la réponse suivante. La fenêtre est de 1M tokens pour un modèle demandé avec `[1m]`, sinon 200k. Un agent Command Code l’affiche aussi, sa fenêtre lue dans `cmd status --json` : celle de son modèle par défaut, donc après un `/model` vers un autre, les tokens seuls. Un agent OpenCode l’affiche aussi, sa fenêtre lue dans le catalogue de modèles d’OpenCode ; un modèle qu’il ne liste pas (un fournisseur configuré à la main), les tokens seuls. Un agent Codex l’affiche aussi, tokens et fenêtre lus dans sa transcription.

![Ce qu’un agent a consommé : tokens, coût, par réponse, et la répartition](images/agent-usage.webp){width=338}

**Ce que contient le contexte** : avec Claude Code et Codex, un clic sur la jauge de contexte ouvre son détail. La **Base** est ce que la CLI envoie avant votre premier mot (prompt système, outils, MCP, compétences, CLAUDE.md ou AGENTS.md), mesurée à partir de la première requête ; puis la conversation depuis la dernière compaction : vos prompts, les réponses et la réflexion, les appels d’outils, les résultats d’outils (détaillés par outil : Read · 23, Bash · 17…), les images, les rappels et les hooks, estimés d’après la taille de chaque message et ramenés aux tokens de la dernière réponse. **Le plus lourd dans le contexte** nomme les plus gros éléments : le fichier lu, la commande lancée, la page récupérée, avec le tour où ils sont arrivés — leurs noms, jamais leur contenu. **Compacter** (deux clics) tape `/compact` dans l’agent une fois son tour terminé : la conversation cède la place à son résumé.

**Ce qu’il a consommé** : à côté de la barre de contexte, **Session** donne les tokens de toute la conversation (Claude Code et Codex) et leur coût aux prix publics des API des modèles (`≈ $3.10`) ; sa ligne dans la liste, le coût. Avec un abonnement, c’est un chiffre de comparaison, pas une facture. Un clic ouvre le détail : réponses, tokens par réponse, et la répartition entre lectures du cache, écritures du cache, entrée et sortie. Prism additionne les chiffres d’usage de chaque réponse de la transcription (le rollout de Codex), jamais son texte ; ceux de Codex aux prix standard d’OpenAI (GPT-6.1 Sol : 2 $ en entrée, 0,10 $ en cache, 10 $ en sortie par million), pas ses tarifs rapides ou à long prompt. **Alerte de coût** (`[agents.claude] cost_alert`, Réglages › Agents › Agent › Claude Code) signale dans les Alertes un agent Claude Code qui dépasse ce nombre de dollars ; le **Par ticket** du Fil de la journée ajoute ce qu’ont coûté les agents d’un ticket.

> [!NOTE]
> Prism suit l’état d’un agent via les hooks de Claude Code et ne garde que des métadonnées (événement, outil, nom de fichier, nombre de tokens du contexte). Il ne stocke jamais le prompt, la réponse ni la sortie d’un outil.

## Terminal ou Chat
Pour les agents Claude Code, Command Code et Codex, **Terminal | Chat** dans l’en-tête choisit comment vous le lisez. **Chat** montre sa conversation à partir de sa transcription, à la place de son terminal (qui continue de tourner dessous) : vos prompts en bulles, ses réponses en Markdown, chaque tour ouvert par une ligne avec son numéro, son heure et ce qu’il a pris (temps, tokens, coût aux prix des API, le modèle qui y a répondu). Les appels et réflexions entre deux de ses réponses se replient en une ligne — **11 étapes** avec ce qu’elles ont fait : fichiers lus, modifiés (lignes ajoutées et supprimées), commandes, autres, et celles en échec en rouge — ; un clic les déplie, chaque appel sur une ligne (un clic montre les dernières lignes d’une commande ou le diff d’une modification), les fichiers lus d’affilée repliés en un. Le tour en cours montre ses trois derniers appels, **N plus tôt** les autres. **Replier ses étapes** (`[agents] fold_steps`, Réglages › Agents › Agent) désactivé montre chaque appel sur sa propre ligne. Ses sous-agents restent hors du repli, chacun une carte à part : son type (Explore, Plan…), ce qu’on lui a demandé, ses appels jusque-là et depuis combien de temps il travaille, **en cours** tant qu’il travaille — en arrière-plan aussi, puisque Claude Code les lance ainsi — ses derniers appels affichés ; une fois fini, ses derniers mots, un clic montre ses appels. Ceux en arrière-plan comptent aussi dans la puce des **tâches en arrière-plan**. Un sous-agent réveillé par un message (le `SendMessage` de Claude Code, les **N agents** du terminal) a sa propre carte là où le message est parti : ce qu’on lui a dit, **en cours** jusqu’à ce qu’il ait de nouveau fini. Au-dessus de la conversation, un rail de puces : son **plan** (étapes faites, celle en cours), ses **tâches en arrière-plan**, sa chaîne (**Ensuite**, ses étapes après son travail) et ses **tours** ; chacune ouvre une bulle au-dessus de la conversation (un clic à côté ou Échap la ferme), celle des tours avec une recherche (sur tous les tours de sa session), un clic menant à ce tour. Remonter jusqu’en haut fait venir ses tours précédents, 30 à la fois, jusqu’au premier de sa session, quelle que soit sa longueur : Prism relit sa transcription plus loin en arrière au besoin, puis seulement ce qu’il écrit depuis. Pendant qu’il travaille, la ligne sous la conversation dit ce qu’il fait et nomme le modèle qui répond : après un `/model`, celui de la réponse suivante ; **Interrompre** (Échap) arrête son tour, l’agent reste. Une question qu’il pose (ses questions à choix multiples) est une carte : choisissez parmi ses choix, ou écrivez vos propres mots, puis **Envoyer la réponse**. En dessous, un seul dock : sa demande d’autorisation sous forme de carte (**Autoriser une fois**, ou **Ses autres choix…** dans le terminal), la zone de saisie, puis son contexte, son usage et **Arrêter**. La zone de saisie lui écrit : Entrée envoie, ⇧Entrée ajoute une ligne (un prompt de plusieurs lignes lui parvient entier). C’est envoyé aussitôt, même pendant qu’il travaille ou après une interruption : sa CLI le garde et le lit une fois son tour terminé. Seul un menu à son écran (une autorisation, sa question) le retient, jusqu’à ce que vous y répondiez ; à son prompt, ses réponses rapides sont dans la zone, et le prompt que suggère Claude Code en est le texte fantôme, **Tab** le prend. Ses tâches en arrière-plan (Claude Code : une commande, un sous-agent ou un moniteur qu’il fait tourner en arrière-plan) ont leur puce tant qu’une tourne, et quelques minutes après la fin de la dernière : combien tournent, ou comment la dernière s’est terminée ; ouverte, chacune avec ce qu’elle est, depuis combien de temps elle tourne ou a tourné, son état (en cours, terminée, en échec, arrêtée) et ce que Claude Code a dit de sa fin, ou le dernier événement d’un moniteur et combien il en a envoyé. Taper `/` propose les commandes slash de sa CLI au fil de la saisie, chacune avec ses arguments, ce qu’elle fait et d’où elle vient (un plugin, le projet, l’utilisateur) : ↑↓ choisissent, Tab ou Entrée la met dans la zone, Échap range la liste. Prism ne tient aucune liste à lui : Claude Code donne ses commandes pour le dossier de l’agent (les siennes, celles du projet et de l’utilisateur, compétences, plugins), demandées de temps en temps sans prompt, donc sans coût ; Codex, seulement vos prompts (`~/.codex/prompts`), sous la forme `/prompts:name` ; Command Code, aucune. Le Chat d’un agent Command Code lit sa session (`~/.commandcode/projects`), trouvée par l’id que donne sa mod : ses prompts, réponses, appels, plan et le coût de chaque tour (le sien) ; ses questions restent des lignes, répondues dans son terminal. La même liste aide dans la zone de réponse du téléphone. Les autres choix de ses autorisations, et ses menus (`/model`…), sont ceux du terminal : **Terminal** y revient. Un agent s’ouvre en Chat par défaut : **Agents affichés en** (`[agents] view`, Réglages › Agents › Agent) réglé sur `terminal` les ouvre plutôt en terminal ; chaque agent garde le choix que vous faites dans son en-tête. Côte à côte, le menu d’un panneau propose aussi **Chat**. Dans son Chat, un lien vers une MR ou un ticket que Prism affiche ouvre son panneau, tout autre lien le navigateur ; ⇧ ou ⌘ enfoncé, le navigateur quel qu’il soit. Un ticket (`SHOP-437`) ou une MR (`!1957`) qu’il nomme ouvre aussi son panneau, comme dans son Terminal.

**Son plan, commenté.** En mode plan (Claude Code), l’agent termine par un plan et attend : son Chat le montre sous forme de carte, **Plan proposé · v1**, plutôt que d’une ligne. Survolez un passage — un titre, un paragraphe, une étape — et cliquez sur le **+** dans sa marge (sur un téléphone, le **+** discret est toujours là) : votre commentaire vient en dessous, le passage éclairé et numéroté ; Entrée l’ajoute, ⇧Entrée ajoute une ligne, Échap annule, ✎ et × le modifient ou le suppriment. Sur plusieurs passages qui se suivent : Maj-cliquez sur le **+** du dernier pendant que la zone est ouverte, ou glissez d’un **+** à un autre ; le commentaire se place sous le dernier, et l’agent lit où il commence et où il finit. Sous le plan, le nombre de commentaires, **Aperçu** (le message que l’agent lira), **Effacer** (deux clics) et une zone pour un commentaire général. Ensuite : **Envoyer les commentaires · continuer à planifier** refuse le plan avec vos commentaires en un seul message, chaque passage cité (il replanifie) ; **Approuver** le laisse continuer, ses modifications autorisées — avec des commentaires rédigés, cela devient **Approuver avec commentaires**, et ils partent avec l’approbation ; **Approuver, demander chaque modification** fait que chacune de ses modifications vous est demandée. La réponse passe par son menu (« Tell Claude what to change »), qui prend une ligne : vos commentaires lui parviennent sur une ligne. Chaque nouveau plan est une version (v2, v3…) : **Modifications** montre ses lignes ajoutées et supprimées depuis la précédente ; un commentaire dont le passage se lit pareil dans la nouvelle version redevient un brouillon, celui dont le passage a changé est compté comme traité (**Ranger** les masque). Une fois le plan approuvé, ses commentaires sont oubliés. ⤢ ouvre le plan dans son onglet **Plan** (le panneau latéral, et Plus sur le téléphone) : la dernière version en grand, les précédentes repliées en dessous. Une longue réponse de l’agent (plusieurs passages, ou longue) a le même **+** : **Envoyer les commentaires** les envoie comme un prompt ; **Commenter ses réponses** (`[agents] comment_answers`, Réglages › Agents › Agent) désactivé laisse ses réponses en lecture seule. Les commentaires sont gardés jusqu’à leur envoi, partagés avec le téléphone : écrits sur l’un, envoyés depuis l’autre. Depuis un téléphone, approuver est une action (`[remote] actions`), commenter, c’est de la saisie (`[remote] typing`, la clé d’accès).

## Le panneau latéral
**Fichiers | Diff | Web | Tâches | Shell | Activité | Lancement | Notes**, dans l’en-tête, ouvrent un panneau à droite, sur le dossier de l’agent (son worktree, sinon son dossier). Chaque agent garde le sien, et sa largeur : ouvrir la vue Web pour l’un laisse les autres comme ils étaient, et revenir à un agent retrouve le panneau qu’il avait ouvert (ou aucun), aussi large qu’il l’a laissé ; un agent jamais redimensionné prend la dernière largeur réglée. Faites glisser le bord pour le redimensionner, double-cliquez dessus pour le réinitialiser. Le bouton d’agrandissement à côté donne au panneau toute la largeur pour un moment (le terminal continue de tourner, masqué) ; lui ou Échap le restaure.

- **Fichiers** : son dossier sous forme d’arborescence, les dossiers repliés sauf ceux qui contiennent des modifications (avec leur nombre), chaque fichier avec son statut git ; un filtre, et **Modifiés** pour ne garder que les fichiers modifiés. Cliquez sur un fichier (ou ↑ ↓, → ← pour déplier et replier, Entrée) pour l’ouvrir dans un onglet, dans un éditeur : le prochain fichier cliqué remplace cet onglet (son nom en italique), un double-clic ou une modification le garde ; un point marque un onglet non enregistré, × le ferme (un second clic s’il n’est pas enregistré). L’éditeur colore le code aux couleurs du thème de Prism, le replie, cherche et remplace dans le fichier (⌘F), va à une ligne (⌘⌥G) ; **⌘S** enregistre, tel que le fichier a été lu : jamais pendant que l’agent travaille (cela attend la fin de son tour, **Attend**), et jamais par-dessus ce que l’agent a écrit entre-temps. Une fine marque dans la marge montre chaque modification par rapport au dernier commit (vert ajouté, bleu modifié, une encoche rouge là où des lignes ont été supprimées) ; un clic montre les lignes telles que dans le commit, ↑ ↓ les autres modifications, **Annuler** les remet. La ligne d’en-tête nomme la fonction, la classe ou le titre où se trouve le curseur ; le Markdown s’affiche rendu (**Source** pour le texte), les images comme des images ; une page HTML s’ouvre dans **Web**. L’en-tête du fichier l’ouvre dans votre éditeur, le télécharge, copie son chemin, ou passe à **Diff**.
  - **⌘P** (ou le bouton ⌘P) ouvre un fichier par des lettres de son chemin (`chkout` trouve `checkout.ts`), les fichiers ouverts et récents d’abord, puis les modifiés : ↵ l’ouvre, ⌘↵ l’ouvre à côté du fichier affiché, ⇧↵ ajoute `@chemin` au prompt du Chat de l’agent. `:42` va à une ligne, `@nom` à une fonction ou un titre du fichier, `#mots` cherche dans tous les fichiers. La palette ⌘K liste aussi les fichiers du dernier onglet Fichiers affiché.
  - **Rechercher** (⌘⇧F, qui n’est pas le mode Zen à cet endroit) cherche dans tous les fichiers du dossier pendant la frappe — suivis et non suivis, `.gitignore` respecté — avec **Aa** (casse), **W** (mots entiers), **.\*** (une expression régulière), les fichiers à inclure (`src/**`, `!*.test.ts` : un nom seul correspond dans n’importe quel dossier) et **Modifiés**. Une ligne trouvée ouvre son fichier à cet endroit, les résultats marqués. ▸ affiche **Remplacer** : **Tous** écrit chaque fichier trouvé (un second clic confirme), jamais pendant que l’agent travaille ni par-dessus un fichier que vous avez modifié sans l’enregistrer.
  - Des lignes sélectionnées : une petite barre sous elles **demande à l’agent** à leur sujet (une question tapée là, envoyée avec les lignes et leur emplacement), **les ajoute à son prompt** (son Chat, à envoyer avec d’autres), en fait une **note** (TODO, dans les notes du dépôt), ou copie leur emplacement (`src/a.ts:12-15`).
  - Quand l’agent modifie un fichier ouvert dans l’éditeur, il est relu sur place (là où vous étiez, ses nouvelles lignes éclairées un instant). Si vous l’aviez modifié sans l’enregistrer, un bandeau le dit : **Comparer** montre sa version face à la vôtre, une modification à la fois (Garder conserve la vôtre, Rejeter prend la sienne), **Prendre sa version**, ou **Garder la mienne** (enregistrée par-dessus sa version).
  - À partir de 640 pixels de panneau, l’arborescence devient une colonne et ◫ montre deux fichiers côte à côte (⌥-clic sur un onglet, ou ⌘↵ dans ⌘P, pour en ouvrir un à côté). Réglages › Agents › Fichiers : **Touches Vim** (`:w` enregistre), **Renvoyer les longues lignes à la ligne**, **Taille du texte**, **Rechargement à chaud**, **Résultats de recherche**.
- **Diff** : **Non commité** (par rapport à `HEAD`) ou **Branche** (toute la branche par rapport à sa base, ce que la MR portera), rendu comme une revue de MR. Les fichiers Markdown s’y lisent rendus aussi. C’est aussi une revue que vous menez avec l’agent :
  - **Notes** : le **+** de la marge sur une ligne écrit une note à l’agent ; glissez le long des **+**, ou un Maj-clic sur une seconde ligne, pour une plage. Les débuts de note (*Pourquoi ça ?*, *Plus simple :*…) commencent la phrase pour vous.
  - **Sur un bloc de modifications** : survolez son en-tête pour **Expliquer**, **Ajouter un test** ou **Annuler** : chacun écrit une note sur tout le bloc, à compléter ou à envoyer telle quelle. Prism ne modifie jamais le worktree lui-même : c’est l’agent qui le fait.
  - **Brouillons** : les notes attendent en bas du panneau, gardées par agent même si Prism quitte. **Aperçu** montre le prompt que l’agent lira (chaque note avec son fichier, ses lignes et le code cité), **Insérer** le tape dans son prompt sans Entrée, **Envoyer** (`⌘↵`) le soumet.
  - **Pendant que l’agent travaille**, Envoyer envoie aussitôt : il lit les notes une fois son tour terminé (**Interrompre et envoyer** arrête d’abord son tour, pour qu’il les lise maintenant). Seul un menu à son écran (une autorisation, sa question) les retient, jusqu’à ce que vous y répondiez.
  - **Après l’envoi**, les notes restent sur leurs lignes : *modifié depuis* une fois que l’agent y a touché. **Depuis mes notes** ne garde que les fichiers qui ont bougé depuis. **Résoudre** replie une note ; les notes résolues sont oubliées au commit suivant.
- **Vue Web** : **Ouvrir…** choisit ce qu’il faut afficher : **Dossier**, les pages, documents et images du dossier de l’agent (HTML, SVG, PDF, Markdown, texte, images) sous forme d’arborescence, ou **Artefacts**, les pages que l’agent a écrites dans le scratchpad de sa session, les plus récentes en premier (affichés en premier quand l’un a moins d’une heure). Tapez pour chercher dans l’un ou l’autre, ↑ ↓ et Entrée pour ouvrir, Tab pour basculer. **Fichiers ignorés par git** ajoute ce que `.gitignore` laisse de côté (une maquette, un rapport de build), grisé ; les dépendances et caches (`node_modules`, `target`…) ne sont jamais listés. Vous pouvez aussi taper un chemin dans l’adresse (complété à la saisie), cliquer sur un fichier HTML dans Fichiers, ou indiquer un serveur local (`http://localhost:…`). Le Markdown s’affiche rendu et le texte tel quel, dans le thème de Prism.
- **Tâches** : ce que déclare le dossier, trouvé dedans et dans ses sous-dossiers jusqu’à **Profondeur des tâches** (`tasks_depth`, 3 niveaux par défaut : le `web/`, le `apps/api/src/` d’un monorepo ; 0 pour le dossier seul ; jamais dans les dossiers cachés, `node_modules`, les builds) : les recettes `just`, les tâches `task` et les scripts `package.json` (lancés avec pnpm, yarn, bun ou npm, d’après `packageManager` ou le lockfile). Cliquez sur l’une pour la lancer dans le shell affiché dans **Shell** (sinon le premier à son prompt, sinon un nouveau), qui s’affiche alors ; une recette qui a besoin d’arguments est seulement tapée là, pour que vous la terminiez. Si ce shell est occupé (un serveur de dev), Prism propose de la lancer dans un nouveau shell, ou d’envoyer d’abord Ctrl-C. Sans `just` ni `task` installés, Prism lit le fichier lui-même, et le dit. Un clic sur l’en-tête d’un fichier replie ses tâches (⌥-clic : tous les fichiers) ; Prism le retient pour les agents du même dépôt, et un filtre les réaffiche toutes. L’**☆** au bout d’une tâche la marque comme faisant partie de la stack du dépôt (tous ses worktrees partagent les étoiles) : le bloc **Serveurs de dev** démarre les tâches étoilées.
- **Notes** : les notes ouvertes du dépôt où travaille l’agent (celui de son worktree, ou le clone qui contient son dossier), les rappels d’abord : **Envoyer** en donne une à l’agent (comme le ➤ du bloc Notes : aussitôt, retenue seulement tant qu’un de ses menus attend une réponse ; un TODO passe en DOING) ; au survol, **TODO | DOING | DONE** règle son statut (celui qu’elle a, cliqué à nouveau, le retire ; DONE la sort de la liste), un rappel a **Fait**, un double-clic sur son texte (ou le crayon, sur le téléphone aussi) le modifie — Entrée enregistre, ⇧Entrée ajoute une ligne, Échap annule — et ✕ puis **Supprimer ?** la supprime ; la zone de saisie classe une nouvelle note sous ce dépôt, **Toutes les notes** ouvre le bloc Notes filtré dessus. Voir [Les notes d’un dépôt](prism:help/notes).
- **Activité** : ce qu’a fait l’agent, d’après son seul journal de hooks (l’outil, le fichier, la première ligne de la commande, sa durée, s’il a échoué ; jamais sa sortie) : un résumé (fichiers lus et écrits, commandes et échecs, autorisations attendues), une bande du temps passé à lire, écrire, lancer des commandes et vous attendre, la chronologie, par tour (votre prompt, puis ce qu’il a fait jusqu’à la fin de son tour : un clic sur l’en-tête d’un tour replie ou affiche son détail, **Tout replier** les replie tous), filtrée par **Fichiers**, **Commandes** ou **Attentes et tours**, et les fichiers qu’il a touchés. Quand la même commande échoue trois fois de suite sans rien d’écrit entre-temps, un encadré dit qu’il tourne peut-être en rond, avec **Interrompre** et une note tapée dans son prompt (non envoyée) ; sa ligne dans la liste affiche `↻ ×3`, et à cinq fois, les Alertes.

![L’onglet Activité : un résumé, la bande du temps, un agent qui tourne en rond, sa chronologie par tour, à côté de son Chat](images/agent-activity.webp)

- **Lancement** : ce avec quoi l’agent a été lancé, tel que c’était alors : l’action qui a ouvert le lanceur, son titre, sa CLI, où (le nouveau worktree demandé, ou le dossier), les autorisations, le type, les étiquettes, tout son prompt (**Copier**) et ses étapes **Ensuite**. Un titre, un type ou des étiquettes changés depuis sont signalés, pas réécrits. **Relancer…** ouvre le lanceur rempli à l’identique (un bandeau le dit ; **Repartir de zéro** le vide) : un nouvel agent et une nouvelle conversation, dans un nouveau worktree du même dépôt et de la même base sous le prochain nom libre, ou dans le même dossier tant qu’il existe ; ses étapes reviennent, pas leur déroulement. Un `⇧`-clic lance immédiatement. Pour reprendre la même conversation, c’est toujours **Redémarrer** ou **Reprendre**. Un agent lancé avant que Prism ne garde son lancement ne montre que son prompt.

- **Shell** : des shells de connexion dans le dossier, pour vos propres commandes pendant que l’agent travaille, un onglet chacun avec ce qu’il fait tourner (un point vert : un programme l’occupe). **+** en ouvre un autre, pour qu’un serveur de dev continue de tourner dans l’un pendant que vous testez dans le suivant. tmux les garde comme l’agent : changer d’onglet ou d’agent n’arrête rien. `exit` ou **×** en ferme un (un second clic s’il fait tourner un programme) ; fermer l’agent, ou supprimer son worktree, les ferme tous.

Le menu ⋯ ouvre le dossier dans le Finder, un shell ou votre éditeur.

## Plusieurs agents côte à côte
Les boutons au-dessus de la liste divisent la vue : un agent, deux côte à côte, deux l’un au-dessus de l’autre, ou quatre en grille (`⌃1`, `⌃2`, `⌃4` ; Ctrl+Alt+1… sous Linux et Windows). Chaque panneau est un agent en direct : son titre, son état et l’action du moment (**Autoriser**, **Reprendre**), ce qu’il montre (son terminal, ou l’un de ses panneaux : Diff, Activité, Web…), son contexte. Le panneau actif, bordé d’orange, est celui de l’agent sélectionné : le clavier, la liste, `⌘[` / `⌘]` et `⌘.` agissent sur lui, et `⌥←` `⌥→` `⌥↑` `⌥↓` passent à l’agent de ce côté.

Un clic dans la liste ouvre un agent dans le panneau actif ; un `⌘`-clic, ou un glisser sur un panneau, le met dans un autre (un vide d’abord). Un agent s’affiche dans un panneau au plus, et la liste numérote ceux affichés. **×** vide un panneau, l’agent continue. Un double-clic sur le titre d’un panneau, ou `⌘↵`, lui donne toute la vue, avec son en-tête complet (liens, type, étiquettes) ; `⌘↵` à nouveau revient. **Suivre qui attend** (le réveil, à côté des dispositions) amène un agent qui vous attend dans un panneau vide, ou le dernier, et le vide une fois répondu ; celui que vous avez retiré à la main reste dehors tant qu’il attend. La disposition et quel agent est dans quel panneau sont retenus.

## Serveurs de dev
Le bloc **Serveurs de dev** montre, par agent, les serveurs que fait tourner son dossier : un programme dans l’un de ses shells qui écoute sur un port TCP, un serveur que l’agent a démarré lui-même (depuis son outil Bash), ou un conteneur Compose démarré depuis son dossier. Rien à déclarer : Prism les trouve dans l’arbre des processus et les ports en écoute, et nomme chacun d’après la tâche qui l’a démarré. Chaque ligne donne ses ports (cliquez sur l’un pour ouvrir `http://localhost:<port>`), son shell et depuis quand ; **Afficher** ouvre ce shell dans le panneau de l’agent, **Arrêter** lui envoie Ctrl-C (`docker stop` pour un conteneur).

Un serveur dont le shell revient à son prompt reste, avec ses dernières lignes : en rouge quand elles se lisent comme une erreur, par exemple un port déjà utilisé (la ligne dit lequel). **Relancer** tape la même commande dans le même shell ; **×** oublie la ligne. Un serveur arrêté sur une erreur est aussi dans les **Alertes**.

Un agent qui ne fait rien tourner est listé sous **Rien en cours**, avec ses tâches étoilées : **▶ Démarrer** lance chacune dans un nouveau shell. Sans étoile, le bouton ouvre son panneau Tâches, pour étoiler la stack une fois. **Hors de Prism** liste les ports occupés par des programmes que Prism n’a pas démarrés (un `node` oublié, un Postgres Homebrew, un conteneur), programmes système et applications mis à part ; **Tuer** demande deux clics.

Activez-le dans Réglages › Agents › Serveurs de dev (`[dev_servers] enabled`), puis ajoutez le bloc à une page. Il lit tous les `poll_seconds` (5) ; `scan_outside = false` exclut les ports hors de Prism.

## Chaînes : quand c’est fait, ensuite…
![Le Ensuite du lanceur : test, MR brouillon, puis un agent de revue sur votre feu vert](images/agent-launcher.webp){width=620}

Dans le lanceur, **Ensuite** ajoute des étapes qui suivent l’agent une fois son travail fait : **Tâche** (une commande lancée dans son dossier, son code de sortie lu), **Prompt** (envoyé à l’agent quand il vous attend), **MR brouillon** (sa branche poussée, une MR brouillon ouverte vers la branche dont elle est partie, intitulée d’après son ticket, décrite par ses commits), **Agent de revue** (un second agent en Planifier d’abord, `{mr}`, `{ticket}` et `{branch}` remplis dans son prompt) et **Notifier**. Chaque étape a sa condition : **une fois terminé**, **s’il a réussi**, ou **me demander d’abord** (elle attend votre **Démarrer**, ou **Passer**). Les chaînes toutes prêtes (**Test → MR brouillon**, **Test → MR → revue**, **Auto-revue**) remplissent les étapes en un clic.

Une tâche qui échoue revient à l’agent une fois, avec la fin de sa sortie, et se relance quand l’agent a fini ; en échec deux fois, la chaîne s’arrête là. Sous l’en-tête de l’agent, la chaîne montre chaque étape (✓ faite, ◌ en cours, ⏸ vous attend, ✕ en échec), avec **Arrêter la chaîne**.

![Une chaîne sous l’en-tête de l’agent : les tests sont passés au second essai, la MR brouillon est ouverte, la revue attend votre feu vert](images/agent-chain.webp)

Rien n’est mergé, et Prism ne pousse aucune MR depuis la branche principale ou une branche de release. Les chaînes survivent à un redémarrage de Prism, et tournent tant qu’il tourne.

## Images et fichiers dans le prompt
Déposez des images, des PDF ou n’importe quel fichier sur le prompt du lanceur, collez-y une capture d’écran (`⌘V`), ou cliquez sur **Joindre** : chacun s’affiche en vignette et son chemin va dans le prompt sous la forme `@path`, que Claude Code lit. Déposez des fichiers sur le terminal d’un agent en cours : ils sont enregistrés dans son dossier, `.prism/attach/` (ajouté au fichier d’exclusion propre à son git, jamais à `.gitignore`), et leurs chemins tapés dans son prompt, non envoyé, pour que vous le terminiez. Les fichiers d’un agent pas encore lancé attendent dans le dossier de travail de Prism, un mois au plus.

Dans son **Chat**, le bouton image à gauche de la zone de saisie (sur un téléphone aussi : vos photos ou l’appareil photo) joint des images, comme en coller une dans la zone (`⌘V`). Chacune est enregistrée dans `.prism/attach/` et s’affiche en vignette au-dessus de la zone (× la retire) ; son `@path` va dans votre message et part avec lui. Une image lourde (plus de 1,5 Mo) ou que l’agent ne lit pas (le HEIC d’un téléphone) part en JPEG de 2048 pixels au plus. Depuis un téléphone, elle part avec votre message, donc seulement quand la saisie est activée (`[remote] typing`).

## Dicter un prompt

Sur l’ordinateur, le prompt d’un agent peut se dicter plutôt que se taper : le **micro** à côté du bouton image de la zone de son Chat, et à côté des commentaires d’un plan, des mots libres d’une question et du prompt du lanceur.

- **Maintenez-le** (ou maintenez **Fn** sur macOS, **Ctrl ⇧ Espace** sur Linux, quand la zone a le focus) et parlez ; relâchez : le texte arrive au curseur. **Cliquez** pour une longue dictée : un clic démarre, le suivant insère le texte.
- Pendant l’enregistrement, une barre sous la zone montre la durée, le niveau du micro et son nom ; **Échap** annule, rien n’est inséré.
- Le texte n’est jamais envoyé seul : relisez-le, puis envoyez comme d’habitude (le brouillon est gardé comme du texte tapé).
- Un micro coupé, éteint ou trop bas (les seuils `[sound]` du bloc Son) est signalé avant d’enregistrer, avec **Remonter** en un clic.

Rien ne quitte l’ordinateur : la reconnaissance vocale de macOS, forcée sur ce Mac, ou **whisper** intégré à Prism (macOS et Linux), dont le modèle se télécharge une fois depuis les Réglages (`base`, 142 Mo, par défaut ; `small` reconnaît mieux le jargon). Les noms du dépôt, de la branche et des fichiers sont passés comme vocabulaire. L’audio reste en mémoire et est jeté une fois transcrit.

## Command Code
Avec **CLI d’agent** sur `command-code`, les nouveaux agents lancent [Command Code](https://commandcode.ai) (`cmd`) au lieu de Claude Code, et les libellés, le logo et l’usage du forfait suivent. Un agent garde la CLI avec laquelle il a été lancé. Un dépôt peut nommer la sienne (**Réglages › Code › Dépôts › Agent**, `[[repos]] agent`) : les agents lancés dans son clone ou ses worktrees utilisent celle-là, et la commande du lanceur l’affiche — Command Code partout sauf Claude Code sur un dépôt, par exemple. Les différences :

- Prism le suit via un mod qu’il charge (`--mod`) plutôt que des hooks ; les mêmes métadonnées seulement. Command Code n’a pas d’événement d’autorisation : un outil encore en attente après 1,5 s compte comme en attente d’une autorisation.
- Prism crée le worktree de l’agent avant de l’y lancer ; **Redémarrer** reprend la conversation par son identifiant Command Code.
- Pas de mode d’autorisation **Auto**. Ses **Artefacts** sont les pages qu’il écrit dans le scratchpad de sa session (`/tmp/commandcode-<uid>/…`), comme ceux de Claude Code.
- La barre d’état montre ses fenêtres de 5 h et de la semaine ; son panneau ajoute le mois de facturation, jour par jour comme la semaine.

## OpenCode
Avec **CLI d’agent** sur `opencode` (ou `[[repos]] agent = "opencode"`), les nouveaux agents lancent [OpenCode](https://opencode.ai) (`opencode`), avec les fournisseurs et modèles de votre propre configuration OpenCode. Les différences :

- Prism le suit via un plugin qu’il ajoute à votre configuration pour cet agent seul (`OPENCODE_CONFIG_CONTENT`, vos propres plugins restent) ; les mêmes métadonnées seulement. Les tours d’un sous-agent ne sont pas ceux de l’agent.
- Prism crée le worktree de l’agent avant de l’y lancer ; **Redémarrer** reprend la conversation par son identifiant OpenCode (`opencode --session`). OpenCode n’a pas de nom de session : le titre reste celui de Prism.
- **Autorisations** : **Planifier d’abord** démarre son agent `plan`, **Accepter les modifications** autorise les modifications quoi que dise votre configuration (OpenCode les autorise par défaut). **Autoriser une fois** appuie sur Entrée à sa question (*Allow once*) ; **Interrompre** appuie deux fois sur Échap, comme OpenCode le demande.
- Pas d’usage du forfait dans la barre d’état, et pas d’**Artefacts** : OpenCode n’a pas de scratchpad de session.

## Codex
Avec **CLI d’agent** sur `codex` (ou `[[repos]] agent = "codex"`), les nouveaux agents lancent [Codex](https://github.com/openai/codex) (`codex`), avec votre propre configuration et connexion Codex. Les différences :

- Prism le suit via des hooks, comme Claude Code, donnés sur sa ligne de commande (`-c hooks.<event>=…`, vos propres hooks restent) ; les mêmes métadonnées seulement. **La première fois**, Codex vous demande de les examiner (*Hooks need review*) : choisissez *Trust all and continue* dans le terminal de l’agent. Il ne redemande que si Prism se déplace (un autre build) ou que son dossier de données le fait. Codex demande aussi une fois par dépôt si vous faites confiance au dossier.
- Prism crée le worktree de l’agent avant de l’y lancer ; **Redémarrer** reprend la conversation par son identifiant Codex (`codex resume`). Codex n’a pas de nom de session : le titre reste celui de Prism.
- **Autorisations** : Codex n’a pas de mode plan dans lequel démarrer, donc **Planifier d’abord** le lance dans son bac à sable en lecture seule, où il lit et propose sans rien changer ; **Accepter les modifications** le lance dans son bac à sable workspace-write ; **Auto** fait passer ses demandes d’approbation par sa revue automatique (`--approve-for-me`). **Autoriser une fois** appuie sur `y` à sa question (*Yes, proceed*) ; **Interrompre** appuie sur Échap.
- La barre d’état montre ses fenêtres de 5 h et de la semaine, lues dans la transcription de sa dernière session : telles qu’à la dernière requête de Codex, sans appel. Pas d’**Artefacts** : Codex n’a pas de scratchpad de session.

## Continuer avec une autre CLI
Un agent n’est pas lié à sa CLI : **Continuer avec…** le confie à une autre — Claude à sa limite, Codex pour prendre la suite — en gardant l’agent lui-même : son dossier, son worktree, sa branche, son ticket, sa MR, ses notes et son type. Sa CLI est une puce dans son en-tête (**Claude ▾**) : son menu liste les autres CLI trouvées sur l’ordinateur, chacune avec l’usage de son forfait ; le menu ⋯ de l’agent, la palette (*Continuer avec Codex*) et, sur un téléphone, sa feuille ⋯ le proposent aussi.

Aucune CLI ne sait reprendre la conversation d’une autre : la suivante démarre donc d’un **relais**, les mots qu’elle lit en premier, montrés et modifiables dans une fenêtre avant l’envoi :

- **Relais écrit par Prism** (`prism`) : construit depuis la transcription et git, sans appeler de modèle — la demande d’origine, son plan, ses derniers tours (vos mots et la fin de chaque réponse), les fichiers modifiés depuis sa base, ce qui n’est pas commité, ses commits, le ticket et la MR. Gratuit, immédiat, et il marche même quand la CLI précédente est à sa limite. Chaque partie peut être retirée.
- **Résumé écrit par l’agent** (`agent`) : **Demander à Claude** envoie à l’agent précédent une demande de mot de passation ; une fois son tour fini, sa réponse devient le relais. Le meilleur résumé, mais il coûte un tour et l’agent doit pouvoir répondre — pas à sa limite.
- **La tâche seule** (`task`) : sa demande d’origine et son ticket ; l’agent suivant relit le code lui-même.

La fenêtre choisit aussi le modèle, l’effort et le mode d’autorisation de la CLI suivante (ceux de l’agent par défaut). **Continuer** arrête la CLI précédente sur place (un tour en cours est interrompu) et lance la suivante dans le même terminal. OpenCode ne garde aucune conversation que Prism lise : depuis lui, seulement *La tâche seule*.

**À la limite.** Quand le forfait de la CLI d’un agent est épuisé et qu’il attend, un bandeau dans sa vue dit quand le forfait se remet à zéro et propose la moins utilisée des autres CLI (**Continuer avec Codex…**) ; **Attendre** le masque jusqu’à la remise à zéro. Les alertes le montrent aussi (*Agent à la limite de son forfait*), avec la même correction.

**Ensuite.** Son Chat garde au-dessus les tours de la CLI précédente, repliés (**Avec Claude : 47 réponses**), puis le relais comme séparateur (**voir le message**). Son onglet **Activité** liste les CLI qu’il a utilisées, avec pour chacune sa durée, ses réponses et son coût, et leur répartition ; le coût de l’agent (sa ligne, le Bilan, le Fil de la journée) est leur somme. **Revenir à Claude** y rend la main : Claude Code et Codex reprennent leur propre conversation, le relais ne racontant que ce qui s’est passé depuis ; les autres en démarrent une nouvelle.

Réglages › Agents › Agent : **Proposer une autre CLI à la limite** (`[agents] suggest_switch`), **Relais** (`handoff` : celui choisi d’abord), **Tours dans le relais** (`handoff_turns`, 8), **Relire le relais d’abord** (`handoff_review` ; désactivé, la puce, la palette et le menu ⋯ envoient le relais de Prism ou la tâche en un clic). Depuis un téléphone, le relais est de la saisie (`[remote] typing`, la clé d’accès).

## Les sessions Claude Desktop
Vos sessions Claude Desktop apparaissent dans la même liste, avec un bord en pointillés et un badge **Desktop**, groupées comme dans la barre latérale de l’app. **Afficher les sessions Desktop** (`[agents.claude] show_desktop`, Réglages › Agents › Agent › Claude Code) les masque, et elles ne s’affichent qu’avec les agents Claude Code ; masquées, elles ne sont pas comptées non plus. Prism ne lit que leur état sur le disque, jamais leur conversation ; **Ouvrir dans Claude Desktop** en ouvre une là-bas.

## Réponses rapides
Quand un agent attend à son prompt, un clic lui répond : **OK**, **Vas-y**, **Continue**… sous son terminal, dans l’en-tête d’un panneau côte à côte, sur sa ligne du bloc Agents (au survol), dans son alerte et sur le téléphone. Un clic envoie et soumet le texte (jamais deux fois : le même texte tout juste envoyé n’est pas renvoyé) ; un ⇧-clic, ou une réponse non *soumise*, le tape dans la saisie de l’agent, pour le terminer là. Rien ne s’affiche pendant que l’agent travaille ou demande une autorisation : un texte répondrait à la demande d’autorisation.

Réglages › Agents › Réponses rapides (`[agents.quick_answers]`) les désactive, et règle la liste : un libellé, le texte envoyé, soumis ou non. Vide, celles de Prism sont utilisées, dans la **Langue des prompts**. Un texte peut nommer le `{ticket}`, la `{branch}`, la `{mr}`, le `{title}` ou le `{folder}` de l’agent (`Open the MR for {ticket}.`) : une réponse dont la variable manque à l’agent ne lui est pas proposée. Un pack peut fournir la liste d’une équipe ; celle de config.toml la remplace entièrement.

## Actions rapides
Un travail que vous demandez encore et encore à un agent sur le même dépôt — mettre sa branche principale à jour depuis upstream, lancer un scan Trivy, rafraîchir son lock file — est une action rapide : un bouton avec un ⚡ sur son projet dans la vue Agents (groupée par dépôt) et sur le téléphone, et une ligne dans la palette (⌘K, son nom ou celui de son dépôt). Un clic lance l’agent aussitôt, nommé d’après elle, une notification pour l’ouvrir ; ⇧-clic, ou ⌘↵ sur sa ligne dans la palette, ouvre le lanceur prérempli, pour la modifier avant qu’elle parte.

Réglages › Agents › Actions rapides (`[[agents.quick_actions]]`) les liste : un nom, le prompt (`{repo}` et `{base}`, la branche par défaut du dépôt, y sont remplacés), les dépôts où elle est proposée (vide : tous), **Worktree** (un nouveau worktree là où le dépôt en crée ; désactivé, son clone tel quel — ce qu’il faut pour mettre `main` à jour), le **Mode** (`acceptEdits` pour le laisser travailler seul ; vide, celui de la CLI), son **Type**, et son **Modèle** et son **Effort** (vides, ceux de la CLI). Un pack peut fournir celles d’une équipe.

[Ouvrir Réglages › Agents › Actions rapides](prism:settings/quick-actions)

Une session qui a bien marché devient une action rapide sans la réécrire : **Créer une quick action…** dans le ⋯ d’un agent (Session ; archivés compris), **Quick action…** sur la carte « Laissé il y a … » d’un projet et dans l’en-tête d’une session Claude Desktop. Son formulaire arrive prérempli depuis la session : son titre comme nom, son dépôt, worktree ou clone, mode, type, modèle et effort (laissés de côté quand la session tournait sur une autre CLI que celle de son dépôt). Le prompt montre aussitôt son premier message, le nom du dépôt et sa branche de base écrits `{repo}` et `{base}` ; pendant ce temps, un agent de la CLI de la session rédige un seul prompt qui se suffit à partir de tous ceux que vous lui avez donnés, précisions en cours de route comprises, puis se ferme. **Garder celui-ci** l’arrête ; **Revenir au premier message** annule son brouillon. **Enregistrer** l’ajoute à `config.toml` (jamais à un pack) et son ⚡ apparaît aussitôt ; **En faire une routine** ouvre Réglages › Routines sur une nouvelle routine qui la lance. Sur le téléphone, la même chose depuis le ⋯ d’un agent et la carte « Laissé… » ; enregistrer écrit la config, donc demande les actions critiques et votre passkey.

Une routine (Réglages › Agents › Routines) lance une action rapide à heure fixe, ou un **prompt** écrit pour elle seule : un travail qui n’a de sens qu’à heure fixe (« résume les MR mergées depuis {since} ») n’a alors pas besoin d’une action rapide qui encombre les menus. Une telle routine dit elle-même ce qu’une action rapide dirait (worktree, mode, type, modèle, effort) ; sans dépôt, elle tourne une fois, dans le dossier de travail. **Transformer en quick action** déplace son prompt dans une action rapide, pour l’essayer d’un clic.

Sur le téléphone, l’onglet **Agents** liste les agents de Prism (pas les sessions de Claude Desktop) : ceux qui **vous attendent** en premier — la question qu’ils posent, la commande qu’ils veulent lancer, ou leur plan — avec leurs réponses rapides, **Autoriser** et les touches à portée ; puis ceux qui travaillent, puis les inactifs ; les arrêtés se replient en bas. Un appui ouvre le terminal de l’agent. En haut, l’usage du forfait comme dans la barre d’état (la session de 5 h et la semaine, en %) ; un appui montre chaque fenêtre avec sa réinitialisation et la semaine jour par jour. En dessous, **Nouvel agent** en démarre un sur un prompt, dans un nouveau worktree.

Sur le téléphone, la zone sous le terminal d’un agent envoie un texte à vous : **Envoyer** demande votre clé d’accès (Face ID, empreinte), puis l’agent reçoit le texte aussitôt, comme tapé sur l’ordinateur — même pendant qu’il travaille. La clé d’accès est demandée une fois par agent pour la fenêtre de validation renforcée (**Saisie vers les agents**, Réglages › Accès à distance), qui couvre aussi **Prendre la main** ; Retour ajoute une ligne, seul **Envoyer** envoie. Les réponses rapides, 1 2 3, **Interrompre** (Échap) et Autoriser ne demandent pas de clé d’accès. Dans l’un de ses shells, chaque touche est de la saisie (la même clé d’accès), et **Encore** relance la dernière commande du shell (↑ puis Entrée, depuis son historique, quel qu’en soit l’auteur) ; le shell pris en main (**Prendre la main**), ↻ dans la barre de touches fait de même.

Sur le téléphone, une question que pose Claude Code (ses questions à choix multiples) s’affiche dans le **Chat** de l’agent sous forme de carte : chaque question avec ses choix (un seul, ou plusieurs quand elle le dit), choisis là, puis **Envoyer la réponse** ; Prism appuie sur les touches de son menu pour vous, sans le terminal. Une question peut aussi accepter vos propres mots, qui demandent votre clé d’accès comme **Envoyer**. Une fois répondue, la carte montre les réponses reçues. Sur l’ordinateur et le téléphone, un agent qui pose une question **vous attend** (Répondre à sa question), ce n’est pas une autorisation à accorder : **Autoriser** aurait choisi son premier choix.

Sur le téléphone, le terminal d’un agent est toujours à la taille du téléphone, dans une police lisible, et le suit quand le téléphone pivote. Le regarder ne tape jamais rien : la fenêtre de l’agent prend la taille du téléphone pendant que vous la regardez de là, et celle de l’ordinateur quand vous tapez à nouveau sur l’ordinateur ou la fermez sur le téléphone.

Sur le téléphone, les onglets d’un agent sont ceux de l’ordinateur : **Chat**, **Terminal**, **Diff** (non commité ou toute la branche, en lecture seule : les notes de revue s’écrivent sur l’ordinateur), puis sous **Plus** (une feuille) **Fichiers**, **Shell**, **Tâches**, **Web**, **Activité**, **Lancement** (Relancer y ouvre le lanceur) et **Notes** (les notes de son dépôt, chacune envoyée à l’agent, son statut réglé ou supprimée). Sous son nom, son état, sa branche et son étape. Son **Chat** est celui de l’ordinateur, les bulles de ses puces en feuilles venues du bas : un appui sur la ligne de ce qu’il fait montre les dernières lignes du terminal (un autre, le terminal) ; son contexte est une fine ligne au bord du dock (un appui, le détail) ; son autorisation une carte avec **Autoriser une fois** ; les touches de ses menus (1 2 3) et **Interrompre** (Échap) derrière ⌨︎ à côté de la zone de saisie. Son **⋯**, en haut à droite, l’arrête (**Arrêter** : deux Ctrl-C, son dernier écran reste, Reprendre le relance) ou le ferme (**Fermer** : arrêté, son worktree supprimé quand rien ne serait perdu) : un second appui confirme, puis votre clé d’accès, avec les **actions critiques** activées (Réglages › Accès à distance › Exposition). Ses **Fichiers** lisent tout fichier de son dossier ; un fichier caché que git ne suit pas (`.env`, une clé) ou un fichier de `.git/` demande aussi votre clé d’accès, avec les actions critiques activées, puisque c’est là que vivent les secrets : un fichier suivi (`.github/…`, `.gitlab-ci.yml`) s’ouvre comme les autres. Son **Web** montre ses **Artefacts** (les pages qu’il a écrites dans le scratchpad de sa session, les plus récentes d’abord, un point sur celles apparues depuis votre dernier passage, leur nombre sur l’onglet) ou les pages de son **Dossier**, groupées par répertoire ; une page s’ouvre en plein écran, ses scripts et les fichiers à côté d’elle chargés comme sur l’ordinateur, dans un bac à sable qui ne peut pas atteindre Prism ; ↻ la recharge, ↗ l’ouvre dans le navigateur, **Demander un changement…** met son nom dans le prompt de l’agent.

## Tokens
![Le bloc Tokens : le total du mois face au précédent, une barre par jour, et où sont allés les tokens](images/tokens.webp){width=563}

Le bloc **Tokens** additionne ce qu’ont consommé vos outils de code sur une **Semaine** (du lundi au dimanche) ou un **Mois** : chaque session de cet ordinateur, agents de Prism ou non, de Claude Code, Codex, Command Code et OpenCode. Le total vient face à la période précédente (les mêmes jours, pour celle en cours), avec son coût : ceux de Claude Code et de Codex aux prix publics des API (avec un abonnement, un chiffre de comparaison, pas une facture), ceux de Command Code et d’OpenCode tels qu’ils les comptent. Une barre par jour, **‹ ›** pour remonter le temps ; en dessous, où ils sont allés : sortie, entrée, écritures et lectures du cache, les outils, les modèles, les projets.

Avec plusieurs outils, **Tous** ou l’un d’eux seul (un clic sur sa ligne sous **Outil** aussi) : le total, les barres, le coût et la répartition sont ceux de cet outil seul, sur l’ordinateur comme sur le téléphone. Prism lit les chiffres d’usage des outils, jamais ce qui a été dit, et garde les totaux quotidiens pour l’**Historique** (`[tokens] keep_days`), après que les outils ont supprimé leurs sessions ; Réglages › Agents › Tokens choisit les outils (`[tokens] sources`).

## Prism MCP : un agent qui connaît Prism

`prism mcp` est un serveur MCP qu'un CLI d'agent démarre : il donne à l'agent l'aide de Prism, la référence commentée (`config.example.toml`), le schéma de chaque table (types, défauts, ce qui la lit, sa page de Réglages), votre config fusionnée avec ses packs (secrets masqués ; les jetons sont de toute façon dans le trousseau) et les Problèmes. Avec la skill « prism » livrée avec lui, l'agent connaît les mots de Prism (bloc, page, bande, pack…) et sait quel outil appeler.

L'agent n'écrit jamais `config.toml` : il vérifie un changement (`prism_validate`), puis le **propose**. Prism montre la proposition dans un tiroir — la raison de l'agent, le diff, ce qu'elle touche, une clé d'un pack remplacée — et vous l'**appliquez** (deux clics), la **refusez** (votre raison revient à l'agent) ou la **modifiez avant d'appliquer** (l'agent reçoit ce que vous avez changé). Elle s'applique à chaud. Vous la trouvez là où vous regardez : dans le Chat de l'agent, son appel en attente est une carte (sa raison, `+5 · [[repos]]`, les avertissements) avec **Voir le diff**, **Refuser…** et **Appliquer**, puis une ligne qui dit qu'elle a été appliquée, refusée (avec votre raison) ou modifiée ; dans Alertes, une ligne par proposition en attente, **Voir la proposition** l'ouvrant ; dans la liste des Agents, une pastille **1 proposition** sur son agent ; dans la barre d'état, `MCP · n` dans la couleur d'accent. Sur le téléphone, la carte s'affiche, la réponse se donne sur l'ordinateur. Le fichier a changé entre-temps : la proposition est recalculée dessus, à appliquer de nouveau.

Un bloc personnalisé est testé avant d'être proposé : `prism_run_custom_block` l'exécute une fois, sans confiance, dans une sandbox (`sandbox-exec` sur macOS, `bwrap` sur Linux) : ni dossier personnel, ni jeton, un dossier temporaire, le réseau sortant, 20 s et 256 Mo. Sans sandbox sur l'ordinateur, le test est refusé. Le bloc lui-même reçoit votre confiance quand vous l'ajoutez, comme tout bloc qui ne vient pas des Réglages.

- **Configurer Prism** (Réglages › Agents › Prism MCP, ou ✦ **Demander à un agent** en haut de chaque page des Réglages) : un agent dans le dossier de la config, avec le serveur MCP et la skill, la page dans son prompt.
- **Prism MCP pour chaque agent** (`[agents] prism_mcp`) : chaque agent lancé par Prism les reçoit (Claude Code par un plugin, Codex et OpenCode par leur config MCP).
- **Agents hors de Prism** : `prism mcp install claude|codex|opencode` (ou **Ajouter** sur la page) écrit le serveur dans la config utilisateur du CLI et la skill dans son dossier de skills ; `uninstall` les retire.
- `[mcp] enabled` coupe le serveur ; `[mcp] proposals = false` le met en lecture seule stricte (l'agent donne le TOML à coller).

Il joint le Prism du profil qui tourne par un socket local, réservé à son propriétaire ; Prism arrêté, seules l'aide, la référence et le schéma répondent. Il ne lit rien de votre travail (tickets, MR, mails) ni aucun secret.

## Au passage : ce qu’un agent voit hors de sa tâche

En travaillant, un agent voit souvent quelque chose qui mériterait d’être fait mais qui n’est pas ce que vous avez demandé : du code mort, une doc périmée, un test manquant, un TODO confirmé, le même bug ailleurs. Plutôt qu’une phrase de son résumé que vous ne lirez peut-être pas, il le signale avec `suggest_task`, un outil que Prism donne aux agents qu’il lance (Claude Code, Codex, OpenCode), et continue sa tâche. Les appels `spawn_task` des sessions Claude Desktop arrivent aussi.

- **Dans son Chat** : une carte là où il l’a vu — le titre, quoi et pourquoi, les fichiers — à la place de l’appel d’outil. Elle ne bloque rien : ce n’est pas une question.
- **Sur l’agent** : une puce **↗ n**, ses propositions ouvertes ; un clic ouvre la liste sur lui.
- **La liste « Au passage »** : le bouton **↗** au-dessus de la liste des agents (et le bloc **Au passage** d’une page, Plus › Au passage sur le téléphone), par dépôt ; Ouvertes, Lancées, Tickets, Écartées. Deux agents qui voient la même chose (même dépôt, fichiers qui se recouvrent, titres proches) font une seule ligne, vue par les deux.

Chaque ligne : **Lancer…** ouvre le lanceur pré-rempli — son prompt précédé de sa provenance, un nouveau worktree depuis la base ou depuis la branche de l’agent (choisi sur la carte ; la branche de l’agent d’abord quand la tâche dépend de ses changements), le CLI et l’effort de son agent, son type — et Entrée lance. **Après cet agent** l’ajoute à la chaîne de cet agent : lancée quand il a fini. **Ticket** la crée dans le tracker, son résumé, qui l’a repérée et son prompt en description. **Plus tard** la garde sans badge ; **✕** l’écarte, la raison revenant à l’agent.

L’agent apprend ce qu’elle est devenue à son étape suivante (lancée ailleurs : il laisse ces fichiers ; écartée : il ne la repropose pas), et peut en retirer une lui-même (`dismiss_task`) : barrée dans son Chat. Une ligne dont un commit d’une autre branche a modifié les fichiers depuis le dit. Les lignes ouvertes plus vieilles que `stale_days` se replient sous Anciennes ; rien n’est supprimé tout seul.

## Réglages et console
Dans Réglages › Agents › Agent (`[agents]`) :

- **CLI d’agent** (`provider`) : `claude` (Claude Code), `command-code` (Command Code), `opencode` (OpenCode) ou `codex` (Codex), pour les nouveaux agents (sauf si leur dépôt nomme la sienne) et l’usage du forfait.
- **Les actions d’agent ouvrent** (`target`) : `agent` pour le lanceur de Prism, `desktop` pour une session Claude Desktop.
- **Langue des prompts** (`prompt_language`) : la langue des prompts qu’écrivent les actions Claude, `fr` ou `en`, et donc des réponses de Claude.
- **Logs pour une correction** (`fix_log_lines`) : un agent lancé depuis les Alertes pour corriger un pipeline en échec reçoit dans son prompt la fin du log de chaque job en échec (jusqu’à 3 jobs), ce nombre de lignes, 60 par défaut ; 0, aucune : l’agent lit les logs lui-même.
- **Profondeur des tâches** (`tasks_depth`) : combien de niveaux de sous-dossiers le panneau Tâches parcourt pour trouver des fichiers de tâches, 3 par défaut ; 0, le dossier de l’agent seul.

Les actions Claude demandent le travail en quelques mots simples (« Refine ticket ABC-123. », « Review the code of MR !1620. »), jamais par le nom d’une compétence : si le plugin de votre équipe a une compétence pour ce travail, Claude la choisit d’après sa description ; sinon il fait le travail à sa façon.
- **Dossier des worktrees**, **Préfixe de branche**, **Autorisations** (la valeur par défaut du lanceur, dans les termes de chaque CLI), **Taille du texte du terminal**, **Historique de défilement**, **Types**.

Chaque CLI a sa propre page sous Agent (`[agents.claude]`, `[agents.command-code]`, `[agents.opencode]`, `[agents.codex]`) : **Binaire** (`bin`, un nom dans le PATH ou un chemin ; vide, son nom habituel), **Modèle** (`model`, passé en `--model` aux nouveaux agents et à la reprise, ses noms suggérés ; vide, celui par défaut de la CLI) et **Arguments supplémentaires** (`args`, comme `--effort high`), ajoutés à chaque lancement et reprise, où qu’il tourne (par défaut ou pour un dépôt). La page de Claude Code a aussi **Alerte de coût** (`cost_alert` : un agent estimé au-delà de ce nombre de dollars est signalé dans les Alertes ; 0, la valeur par défaut, jamais), **Afficher les sessions Desktop**, **Compter les sessions Desktop** pour les compteurs de l’en-tête et des Alertes, les dossiers des sessions et transcriptions Desktop, et **Rafraîchir le jeton** de l’usage du forfait.

Dans la console, `agent <prompt>` démarre aussitôt un agent sur ce prompt, dans le premier dépôt avec des worktrees, celui que désignent les références de MR sans dépôt d’abord (`agent refine ABC-4661`, ou une commande `/plugin:skill` tapée telle quelle) ; `agent` seul ouvre le lanceur (un nouveau worktree par défaut).
